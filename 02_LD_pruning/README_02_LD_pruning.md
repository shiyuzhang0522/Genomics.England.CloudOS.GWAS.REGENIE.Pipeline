# 02_LD_pruning

Chromosome-parallel LD pruning of high-quality common SNP genotype datasets generated by `01_shared_QC`, for construction of a relatively LD-independent marker set for REGENIE Step 1.

## Overview

This Nextflow pipeline performs LD pruning on the chromosome-specific high-quality common SNP PGEN datasets generated by `01_shared_QC`.

The workflow is intentionally separated from the upstream genotype QC so that different pruning parameters can be tested without regenerating the large HQ-common PGEN datasets.

The current first-pass pruning setting is:

```text
window = 500kb
r2     = 0.2
```

The workflow runs independently across chromosomes 1–22 using PLINK2 `--indep-pairwise`.

## LD-pruning workflow

For each chromosome, the pipeline:

1. Reads the chromosome-specific HQ-common PGEN/PVAR/PSAM files generated by `01_shared_QC`.
2. Confirms that the input genotype files are present and non-empty.
3. Counts input variants and samples.
4. Performs LD pruning with PLINK2:

```bash
plink2 \
  --pfile HQ_common \
  --indep-pairwise 500kb 0.2 \
  --threads 4 \
  --out chrN.LD_pruned
```

5. Writes retained and removed variant lists.
6. Performs post-pruning sanity checks, including confirmation that retained + removed variants equals the input variant count.
7. Writes a chromosome-specific pruning summary.

With `--indep-pairwise 500kb 0.2`, the retained variants are relatively LD-independent within the specified 500-kb windows, with retained variant pairs constrained by the pruning algorithm to avoid pairwise LD above the specified `r²` threshold.

## Input data

The pipeline requires one runtime input:

```text
--hq_pgen_root
```

This directory should directly contain chromosome-specific outputs from `01_shared_QC`:

```text
<hq_pgen_root>/
├── chr1/
│   ├── chr1.HQ_common.pgen
│   ├── chr1.HQ_common.pvar
│   └── chr1.HQ_common.psam
├── chr2/
│   ├── chr2.HQ_common.pgen
│   ├── chr2.HQ_common.pvar
│   └── chr2.HQ_common.psam
...
└── chr22/
    ├── chr22.HQ_common.pgen
    ├── chr22.HQ_common.pvar
    └── chr22.HQ_common.psam
```

The current GEL cutaneous melanoma analysis uses 88,690 genetically predicted European-ancestry participants retained after cohort QC.

## Pruning parameters

The default parameters are defined in `nextflow.config`:

```groovy
window = '500kb'
r2     = 0.2
```

These values can be overridden at runtime if additional pruning settings are tested.

The current first-pass analysis uses:

```text
500 kb window
r² = 0.2
```

This setting was selected as an initial stringent pruning configuration for reducing the approximately 8.3 million HQ-common autosomal SNPs to a several-hundred-thousand-marker backbone suitable for REGENIE Step 1.

## Per-chromosome outputs

For each chromosome, the workflow produces:

```text
chrN.LD_pruned.prune.in
chrN.LD_pruned.prune.out
chrN.LD_pruned.summary.tsv
chrN.LD_pruned.log
```

### `*.prune.in`

Contains variants retained after LD pruning. These are the variants intended for the REGENIE Step 1 marker set.

### `*.prune.out`

Contains variants removed by the LD-pruning algorithm.

### `*.summary.tsv`

Contains:

```text
chromosome
input_variants
retained_variants
removed_variants
proportion_retained
input_samples
window
r2
```

## Parallel execution

The workflow creates one independent `LD_PRUNE` process for each autosome:

```text
chr1
chr2
...
chr22
```

These jobs can be executed in parallel by the CloudOS AWS Batch executor.

In the first CloudOS run, all 22 chromosome-specific `LD_PRUNE` jobs completed successfully.

## Genome-wide marker list

The chromosome-specific retained variant lists can be combined manually after the pruning jobs complete:

```bash
cat chr{1..22}/chr*.LD_pruned.prune.in \
  > REGENIE_step1.LD_pruned.variant_ids.txt
```

The total number of retained markers can be checked with:

```bash
wc -l REGENIE_step1.LD_pruned.variant_ids.txt
```

Duplicate variant IDs can be checked with:

```bash
sort REGENIE_step1.LD_pruned.variant_ids.txt |
uniq -d |
wc -l
```

The expected duplicate count is `0`.

## Current implementation note

The current `main.nf` also contains an optional `COMBINE_PRUNED_LISTS` process intended to concatenate the chromosome-specific `.prune.in` files and create genome-wide summaries automatically.

In the first CloudOS run, all 22 chromosome-specific pruning jobs completed successfully, but the final `COMBINE_PRUNED_LISTS` process failed during its file-presence sanity check because Nextflow stages collected input files as symbolic links while the current check uses `find ... -type f`.

This does **not** affect the validity of the chromosome-specific PLINK2 pruning results. The `.prune.in` files from chromosomes 1–22 can be inspected and combined manually as shown above.

## CloudOS execution

The workflow is designed for Genomics England CloudOS using Nextflow DSL2 and has been run with Nextflow `24.04.4` using the AWS Batch executor.

Because the current CloudOS import interface expects `main.nf` and `nextflow.config` at the repository root, the Step 2 files can be copied temporarily to the repository root for workflow import and execution, while the canonical versions remain under `02_LD_pruning/`.

Required CloudOS runtime parameter:

```text
hq_pgen_root
```

The `hq_pgen_root` value should point to the results directory that directly contains `chr1/` through `chr22/`.
